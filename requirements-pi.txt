# Se instaleaza cu tools/setup_pi.sh, NU direct: scriptul alege pachetele

# --system-site-packages. Fara acel flag lista se instaleaza "cu succes" si
# apoi nimic nu merge.
#
# CE NU E AICI, DELIBERAT
#
#   picamera2, libcamera  - din APT (python3-picamera2, python3-libcamera).
#     Sunt legate de stiva libcamera a sistemului si de binarele ei;
#     versiunea de pe PyPI nu se potriveste cu ele.
#   numpy                 - din APT, ca dependenta a lui picamera2.
#     Bookworm 1.24.2, Trixie 2.2.4. NU il fixa aici: o versiune pip peste
#     cea de sistem sparge simplejpeg (§5.24).
#   opencv                - DEPINDE DE DISTRIBUTIE, vezi mai jos.
#
# OPENCV: DOUA CAI, DUPA DISTRIBUTIE
#
#   Trixie   python3-opencv din APT (4.10.0). E construit impotriva
#            numpy 2.2.4 din sistem, deci nu e nimic de rezolvat. Calea
#            preferata: nimic nu se instaleaza peste sistem.
#
#   Bookworm python3-opencv din apt e 4.6.0, adica INAINTE de API-ul nou de
#            ArUco: `cv2.aruco.ArucoDetector` a aparut in 4.7.0. Codul
#            nostru il foloseste peste tot, deci pe Bookworm OpenCV trebuie
#            luat din pip - vezi requirements-pi-bookworm.txt, unde e si
#            explicatia de ce 4.10 si nu 5.x.
#
#   Regula, daca apare o distributie noua: ia OpenCV din apt daca e >= 4.7,
#   altfel din pip, cu o versiune care nu trage numpy peste cel de sistem.
#
# DIAGNOSTIC: conflict pe numpy sau simplejpeg
#
#   `ImportError: numpy.core.multiarray failed to import`, `_ARRAY_API not
#   found`, sau un simplejpeg care nu se incarca inseamna ca numpy a ajuns
#   sa fie instalat IN venv, peste cel din apt. Cauze uzuale:
#     1. venv creat FARA --system-site-packages;
#     2. un `pip install opencv-contrib-python` fara versiune fixata, care
#        ia 5.x si cere numpy>=2 (problema pe Bookworm, unde apt da 1.24.2).
#   In ambele cazuri: sterge venv-ul si reia tools/setup_pi.sh.
#   `tools/preflight_check.py` raporteaza CALEA din care vin numpy si cv2,
#   exact ca sa se vada asta dintr-o privire.
